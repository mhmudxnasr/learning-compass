# Learning Compass — Hermes Context

This repository is Mahmood's private Learning Compass learning operating system.

Read `AGENTS.md`, `PROJECT_CONTEXT.md`, and `CURRENT_STATE.md` before changing the project. They are the authoritative behavior, architecture, and handoff sources.

The concise layer map and routing soul is maintained in `docs/learning-compass-hermes-soul.md` and mirrored into `~/.hermes/SOUL.md`, which Hermes loads as its global identity. Keep detailed contracts here and in the active skills; keep the soul focused on where to route, when to act, and which layer owns the result.

The machine-readable contract at `docs/hermes-contract.json` is canonical for endpoint ownership, permissions, routing policy, side-effect tiers, and the standard specialist receipt. `npm run verify:hermes` rejects drift.

## Product

- Visual system: Scholar's Instrument.
- Loop: capture → curate → consume externally → reflect → notes → review → map update → resurface.
- D1 is canonical. R2 stores large artifacts. Obsidian is archive/export only for extracted notes.
- Nineteen real views remain available, but the primary rail follows Momentum → Inbox → Queue → Notes → Recall → Atlas. Settings → System exposes every allow-listed API operation plus schedules, services, storage, health, and safety; secondary views stay contextual and no fallback screens exist.

## Architecture

- AI routing matrix: basic intro → Inbox; corporate PR → reject or Inbox; practical applied tool → recommendation allowed; major release or hardware analysis → recommendation allowed; low-level training-internals theory → reject.

- Hono Cloudflare Worker in `src/`.
- Vite/Preact/TypeScript client in `client/`.
- Base schema: `schema.sql`.
- Migration order is the numbered sequence in `PROJECT_CONTEXT.md`, from `migrations/0000_brain.sql` (including `migrations/0006_hermes_upgrade.sql`) through `migrations/0023_intelligence_v2.sql`.
- API contract: `docs/API.md`.

## Invariants

- All captures, including share target, Telegram, RSS, and Atom, land in unlimited Inbox. Enabled feeds refresh every six hours.
- Feed orchestration uses `~/.hermes/skills/productivity/rss-feed/SKILL.md`; user-requested refreshes send `{ "limit": 5 }`, paginate imported history, and never bypass Inbox triage.
- Archive keeps feed captures in a pinned RSS/Atom shelf; use `GET /recommendations/list?source=manual` when reporting the clean manual archive.
- Queue contains only queued/in-progress items and normally caps at five.
- Queue owns start, resume, and completion. Hidden sessions preserve linkage; `POST /sessions/:id/return` with `reflection`, `rating`, and `complete:true` closes the handoff and auto-creates the linked reflection note.
- Structured bilingual notes live on the site.
- Lite Visual resolves the exact source/pair, mines the complete source into a checksum-backed evidence packet, reuses cached mining, separates coverage from design passes, and consumes Visual Mind's contract-v2 manifest.
- Lite Visual generates a real linked HTML+PDF R2 pair with source-proportional layouts, source anchors, responsive tablet typography, explicit revision/supersession metadata, and no QA score or release gate. The Worker payload carries generic URL/artifact source references, resumable stages, and evidence/visual cache keys. Uploads enforce only mechanical HTML/PDF signatures and linked-pair uniqueness.
- Lite Visual does not automatically queue Notes Extractor. Notes extraction remains an explicit/manual workflow.
- `visualise_source` is enqueue-only from the Worker: its payload declares `custom_prompt_required` and expected `html`/`pdf` roles. Book payloads additionally require chapterized output with matching `chapter_key`, `chapter_title`, `chapter_number`, and `pair_id` metadata on each HTML/PDF pair. Hermes owns source-specific prompting, mining, Visual Mind asset planning, rendering, upload, and completion.
- Book visualisation requests add `book_mode=true`, `visual_mode=book_annotation_companion`, and `chapter_outputs=true`; Hermes creates one linked HTML/PDF pair per chapter with stable chapter metadata and mines complete chapters. The Books shelf exposes both formats and stores finished state per chapter. Repeated requests for one source reuse the idempotent job.
- **Books chapter UI**: The Books page expands/collapses chapters on book title click. Each chapter row shows number badge, title, status, file links (HTML/PDF/NBLM), upload buttons for missing files, and Finish/Undo toggle. Chapter file uploads use existing `POST /artifacts` endpoint with chapter metadata (`chapter_key`, `chapter_title`, `chapter_number`, `role`, `pair_id`).
- Lite Visual PDFs use portrait-tablet typography: 15pt body text, readable supporting text, portrait-safe margins, and single-column print layouts even if that increases page count.
- Visual Mind assets use contract v2 (`~/.hermes/skills/visual-mind/references/visual-contract.schema.json`): SHA-256 identity, source anchors, typed placements, learning roles, and style locks. Gemini API is the sole OCR/image-generation provider; deterministic Mermaid/SVG/chart rendering remains allowed, while local OCR, alternate providers, and local-generation fallbacks are forbidden. Lite Visual embeds manifest assets as Base64 Data URIs at their declared placements.
- A reflection supplied to Hermes is explicit feedback: `learning-compass-operating-system` preserves it verbatim, queues exactly one Taste Mapper analysis, and never follows it with a recommendation. Taste Mapper may return proposals or an evidence-backed `no_change`. Typed profile proposals auto-apply only at confidence ≥0.8 with a direct user statement or two evidence items; superseding an explicit user assertion requires direct contradiction or confidence ≥0.95 with three evidence items. Every application is versioned and undoable; weaker evidence stays pending in Learn → Activity.
- Explicit `retain` or `apply` disposition queues Notes Extractor with `output_contract=learning_units_v1`; legacy clients without disposition retain the old 7–10 bridge. Extraction writes anchored Units, an editable source note, and Unit-linked SRS drafts. User approval activates cards; drafts and approved cards remain deletable. The product supports per-block English/Arabic direction, while Mahmood's current extractor preference is English-only notes with preserved Arabic quotations inline.
- Source notes expose an explicit re-run action when an older extraction is incomplete. Lite Visual never starts extraction automatically.
- Hermes model order is explicit and verified: OpenCode Go `deepseek-v4-flash`, OpenCode Zen `deepseek-v4-flash-free`, OpenAI Codex `gpt-5.6-luna`, then Nous `tencent/hy3:free`.
- Handwritten PDF annotations are personal reflection data: preserve them with page anchors, flag uncertain OCR, and never merge printed source claims into the user's voice.
- Feedback never triggers a recommendation automatically.
- Compass Intelligence V2 is the canonical recommendation workflow: resolve the active Learning Thread, research fit/bridge/challenge lanes, submit three structured-evidence candidates first, and expand only after justified abstention up to eight. Send no client scores. The Worker owns reachability, entity normalization, semantic deduplication, policy exclusions, Thread contribution, clean-outcome ranking, calibrated confidence, and shadow V1/V2 receipts. Require explicit Start and feedback. `dismissed`/`not_now` is neutral; bad-fit decline and abandonment are explicit eligibility signals; ratings, dispositions, and later learning evidence are separate utility signals. V2 serving activates only through the rollout gate. Queue-fill remains explicit and feedback never auto-chains a recommendation.
- Legacy Discovery may stage a `skill_revision`, but it never writes an installed skill file. `learning-compass-self-evolution` is the only path from staged evidence to a verified skill-source change.
- NotebookLM is the grounded knowledge corpus for Hermes. Use notebook `https://notebook.google.com/notebook/2c8a58a9-32b8-45db-804f-b48bf756e82c`.
- NotebookLM sync is feedback-driven and Hermes-controlled: when `taste-rec` recommends an item and Mahmood later gives explicit feedback, `taste-mapper` sends the complete relevant corpus update and feedback context to NotebookLM during that workflow. Do not create a background D1-to-NotebookLM sync job for every mutation.
- Send clean original source material and Mahmood's own reflections, notes, ratings, and feedback. Exclude generated Egyptian-Arabic translations, generated summaries, Lite Visual HTML/PDF companions, and any AI-written text unless Mahmood explicitly confirms it is his own thought. Use the original source URL/transcript/PDF/web text instead of Lite Visual output.
- NotebookLM queries must identify the role as Mahmood's grounded Taste Strategist and Chief Knowledge Officer, include the complete available relevant corpus, enforce all taste exclusions, cite exact source evidence, and flag contradictions. Studio generation is never automatic; explicit requests execute immediately. For a Learning Compass source-specific request, create a fresh per-source notebook, add the link as a Website source, start the requested artifact without downloading/uploading or waiting, and immediately save that notebook URL on the matching site item. Direct artifact requests may use the normal deduped wait/download flow.
- NotebookLM interactions use pinned `PleasePrompto/notebooklm-mcp@2.0.0` (`notebooklm_*` MCP tools) as the primary engine and `teng-lin/notebooklm-py` as the direct Python API & CLI backup engine. Playwright DOM automation is completely removed.
- Recommendation signals are immutable `learning_events`; `recommendation_outcomes` is the clean per-source projection. Administrative exclusions never become negative taste. `learning_value_v2` weights available rating 25%, explicit disposition 25%, and strongest downstream evidence 50%. Typed profile state lives in `profile_assertions` with append-only revisions; `self_improvement_runs` records no-change, apply, deploy, and rollback receipts.
- Insights → Hermes is the operational control surface for queue health, prediction error, engine evidence, alerts, failures, and memory state.
- Insights → Hermes separates utility labels, fit labels, and administrative exclusions; shows typed profile health, v2 shadow gates, clean calibration, and self-improvement receipts. `/analytics/hermes/repair` is snapshot-guarded and deterministic; applying repair, evaluator proposals, backfill, or recalibration requires the active conversation ID. `/analytics/hermes/evaluate` is explicit compatibility only and is never scheduled. Recalibration requires 20 training-eligible v2 outcomes; Compass also requires eight per lane. NotebookLM broker health remains explicit through `/notebooklm/health` and `/notebooklm/recover`.
- Hermes claims only the durable work created by an explicit Learning Compass request; there is no scheduled host poller and job operations are not shown in the site.
- Every Hermes conversation ends with one pass owned by `learning-compass-self-evolution`. Specialists emit one compact evidence handoff; they never rewrite themselves independently. The owner records a change, failed/resumable attempt, or evidence-backed `no_change` when a candidate was evaluated, delegates repository edits to Codex, and may deploy narrow verified system changes only after tests, release gate, rollback capture, and observed live smoke. No candidate means a receipt-level `no_change` without database churn. Never create cron/background self-improvement. Destructive deletion and external publication remain explicit-only.
- Use one stable worker name for claim, heartbeat, complete, and fail calls. Keep `Mozilla/5.0 (compatible; HermesCron/1.0)` in the retained manual runner.
- E2E tests own and terminate Wrangler, Workerd, and Playwright processes.

## Hermes synchronization

### Procedural operating system

- The canonical graph has thirteen active skills/tools listed in `docs/hermes-contract.json`. Retired overlapping skills live outside the active tree and remain disabled; do not restore them as parallel owners.
- `~/.hermes/skills/workflow/learning-compass-operating-system/SKILL.md` is the only entry point for Learning Compass chat. It classifies requests into reflection/feedback, session, capture/triage, recommendation, notes/artifact, proposal review, feed, job recovery, or product-operation procedures.
- The router calls one focused specialist after classification. `learning-compass-site-operator` executes verified Worker API steps; `learning-compass-self-evolution` alone owns the end-of-turn improvement pass, explicit audits, evaluator/repair/recalibration/rollout decisions, skill health, and improvement receipts.
- Every active specialist ends with `owner | observation | evidence | replay | smallest_candidate | confidence | scope`. Only concrete current-conversation evidence reaches self-evolution; otherwise it returns `no_change`.
- Reflection text is preserved verbatim through one `POST /feedback/record`. Numeric ratings mean completion unless explicitly provisional. The response is the canonical receipt for tracked and untracked sources.
- Learning purpose is canonical in `/learning/core/threads`; sources serve Threads rather than representing learning outcomes. Completion must record `retain`, `apply`, `reference`, or `drop` separately from rating.
- Recall uses reference FSRS-6 through `ts-fsrs`; the full per-card state and `scheduler_version=fsrs-6-ts-fsrs-5.4.1` are canonical.
- Notes Extractor jobs with `output_contract=learning_units_v1` must return at least one anchored Learning Unit. Claim, method, and counterclaim Units without anchors are rejected. Complete the exact consolidation run to `closed` or fail it to visible `repair_required` state.
- Mastery is evidence-only. Automated note creation, extraction, mapping, card approval, and administrative work never count as retrieval, transfer, application, or verified mastery.

### Agent control protocol

- Read `GET /agent/capabilities` before acting; it is the source of truth for methods and paths.
- Use `POST /agent/request` with `{method,path,body}`, or `/agent/tools` and `/agent/tool-call` for function-calling clients.
- Use `GET /learning/balance?window=30|90|365` for attention/retention balance across map depth; it is the same read model shown in Coverage and summarized in `/agent/context` for Compass decisions.
- To close the mapping gap, Hermes reads balance plus consumed history, matches completed sources to existing `/brain/tree` nodes, calls `POST /recommendations/map`, and verifies each source record plus the reduced unmapped count. Ambiguous matches remain unresolved; mapping never changes completion, queue state, or reflections.
- Send `x-agent-name` for audit attribution and `x-api-token` for authenticated writes.
- Never guess routes, use arbitrary SQL, or use an external proxy. Preserve queue, SRS, D1/R2, feedback, and Lite Visual invariants.
