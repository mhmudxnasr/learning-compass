## Routing

Every Learning Compass request begins with `learning-compass-operating-system`, which selects one focused procedure:

- Site reads/mutations, Queue, sessions, captures, source records, and feedback: `learning-compass-site-operator`.
- Explicit recommendations or Queue fill: `taste-rec`.
- Branch review and surprise directions: the Branch Deck is an explicit user review desk, not a swipe game. `GET /brain/branch-deck` is the evidence-driven waiting list; `POST /brain/branch-swipe` records the user's explicit decision — `keep`, `prune` (reversible exclusion), `priority`, `hold`, `add`, or `undo` — each writing a reversible typed profile signal, never a fabricated "applied" feedback proposal. `POST /brain/branch-suggest` returns grounded, review-before-commit new-branch ideas and writes nothing; only the user's explicit `add` swipe commits a branch. Whenever Mahmood asks for more branches, every candidate must include one comprehensive plain-language orientation: scope, a concrete example or mechanism, and a clear boundary for what it is not about. Keep evidence and uncertainty available as grounding data, but do not clutter the main card with diagnostic labels. This is map maintenance, not source recommendation or Queue fill.
- Feedback/profile analysis: `taste-mapper`.
- Notes, Learning Units, and recall drafts: `learning-notes-extractor`.
- HTML/PDF reading companions: `lite-visual`, with `visual-mind` for visual assets.
- NotebookLM grounding or explicitly requested Studio work: `notebooklm`.
- RSS/Atom: `rss-feed`.
- YouTube source verification: `youtube-playlist-verification`.
- Repository, migration, deployment, and live-operability work: `recommendations-worker-ops`; delegate repository edits to Codex when appropriate.
- System improvement evaluation: `learning-compass-self-evolution` only.

Use `learning-compass-site-operator` as the mutation layer. Read `GET /agent/capabilities` before acting, read the target before a write, use the allow-listed agent API, provide the required audit identity and Cloudflare-compatible User-Agent, then re-read the affected record. Every specialist receipt uses: `intent → target → before → mutation/job → after → evidence → blocker`.

## Non-negotiable behavior

- Every capture enters the unlimited Inbox. Queue normally has at most five queued/in-progress items; overflow needs explicit override.
- Consumption happens at the real source and is tracked through sessions.
- Preserve raw feedback verbatim through exactly one `POST /feedback/record`; it owns tracked and untracked feedback plus completion, so never duplicate the reflection with `POST /sessions/:id/return`. Rating and `retain|apply|reference|drop` are separate. Feedback never triggers another recommendation.
- Notes are English-only for Mahmood, with original Arabic quotations preserved inline. Retain/apply consolidation uses `output_contract=learning_units_v1`; claim/method/counterclaim Learning Units require source anchors. Only approved drafts enter Review.
- Mastery requires retrieval, explanation, transfer, decision, artifact, or application evidence. Administrative actions and generated notes never prove mastery.
- Recommendation work is explicit-only. Resolve the active Thread and one intent, read `/compass/context`, check mastered/consumed/excluded sources, research current primary sources on the web, and submit 3–8 URL-anchored candidates with substantive editorial evidence. Route a basic intro for an already-used tool to Inbox/RSS; reject corporate PR; allow a practical applied tool, major model release, or AI hardware analysis when it fits; reject low-level training-math theory. The Worker owns validation, deduplication, scoring, abstention, and receipts. Normal requests return one fit pick and wait for explicit Start. Books require `allow_books: true`. Bridge/challenge require explicit exploration.
- Islamic recommendations must be original lectures/khutbahs/talks by trusted Sunni scholars; no book-derived material. Respect all durable exclusions in `AGENTS.md` and the live profile.
- Lite Visual creates one linked HTML+PDF pair, or one pair per book chapter, from complete checksum-backed source mining and a coverage matrix. New companions are Arabic-first RTL with real English technical terms explained in context. There is no subjective QA gate and no automatic Notes Extractor chain.
- YouTube transcript mining for visual work is Arabic-first: use the shared `fetch_transcript.py` adapter with `ar,ar-SA,ar-EG,en` priority. English is fallback-only when Arabic is genuinely unavailable. Never use `YouTubeTranscriptApi.fetch()`'s default English-only language list, and never treat an Arabic transcript as an adapter failure.
- NotebookLM uses only original source material and Mahmood-authored reflections/notes for corpus grounding. Generated summaries, translations, and companions are not his voice. Do not create background Studio work.
- No scheduled learning-core poller, autonomous recommendation, routine self-improvement message, or background media generation.
- Self-evolution is conversation-bound. Specialists emit evidence, not self-edits. Only `learning-compass-self-evolution` may accept a concrete improvement candidate after replay/tests. No evidence means no change and no database churn. Destructive deletion and external publication remain explicit-only.
- When a concrete tool, adapter, prompt, or workflow failure is observed, `learning-compass-self-evolution` must capture the exact error, reproduce it, repair the narrowest owning layer, add a regression test/validator, replay the original path, and write scoped `skill_procedure` evidence. A reproducible repairable failure cannot be closed as `no_change`; blocked repairs close as `failed` with a resumable next step.
- Lite Visual release validation must block unresolved placeholders, unfinished English fragments in Arabic prose, duplicate visual retrieval prompts, and malformed figure-caption separators. Raw auto-transcript text may only appear as clearly labeled collapsed evidence, never as the main reading path.
- Use the repaired Yiqeen companion as the reusable quality baseline for future visual files: Arabic orientation plus purposeful reader map, edited source-faithful prose, raw transcript only as collapsed optional evidence, source-specific visuals with unique retrieval questions/takeaways, computed metadata, and verified screen/print behavior. Reuse the quality decisions, not the exact source-specific layout.
- Visual batch repair rule (2026-08-12): never use a fixed four-visual quota or shared mutable output directory. Each source gets an isolated workspace; sub-agents may draft only, while the owning specialist serializes critic, HTML/PDF rendering, full-page PDF inspection, upload, deletion, and canonical-record verification. `visual_plan`, distinct claim/section placement, and a passing critic receipt are mandatory.
- Source-depth protection rule (2026-08-12): a long source may never be reduced to a tiny polished summary. The finished rendered HTML must be measured against the complete evidence packet and meet the dense-source floor (at least 35% of source words, capped at 6,000, with a 2,500-word minimum once the source exceeds 5,000 words). A sub-agent's claimed word count is never evidence; the owning pipeline must render, measure, validate, and reject shallow output before upload. Regional transcript tracks such as `en-US` must be discovered through the adapter fallback and recorded in the evidence packet.
- PDF print QA is mandatory: render and inspect every page before upload. Reject orphaned boundary boxes, footer-only or near-empty pages, excessive unused whitespace, broken page rhythm, clipped content, and malformed Arabic glyphs. Text-heavy Arabic SVG must be rasterized to a verified PNG or rebuilt with print-safe HTML/CSS; never apply global unbreakable pagination rules.
- Never expose credentials or secrets. Keep private/local network access deny-by-default unless the operator procedure explicitly authorizes a known Learning Compass service.
