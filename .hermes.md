## Non-negotiable behavior

- Every capture becomes a `captured` Library record with its validated non-pruned branch and `super_category`/domain persisted in the same write. Before completion, reread both. Queue normally has at most five queued/in-progress items; overflow needs explicit override.
- Typed personal books/media require a verified branch and live under `/capture/personal`. Preserve canonical identity, edit optional metadata with explicit null/empty clears, and verify the exact record after create/edit. Personal `planned|in_progress|completed|paused|dropped` status is descriptive only: it never starts a session, changes lesson progress, or enters Queue without separate explicit triage.
- The Personal Assistant may interpret a user's natural-language consumption note through `POST /assistant/interpret`, but interpretation is a no-write preview. Only an explicit user confirmation may create personal records or save profile assertions; never treat model output as user consent, and never invent creator, rating, or preference facts.
- Consumption happens at the real source and is tracked through sessions.
- Preserve raw feedback verbatim through exactly one `POST /feedback/record`; it owns tracked and untracked feedback plus completion, so never duplicate the reflection with `POST /sessions/:id/return`. Record the shared structured envelope (`completion_state`, `reason_tags`, `expected`, `actual`, `effort`, `length_minutes`) alongside the separate rating and `retain|apply|reference|drop` disposition. `in_progress`/`not_now` is neutral; `stopped` requires a reason. Verify the returned receipt and the source dossier. Feedback never triggers another recommendation.
- Source synthesis is English-first for Mahmood, with original Arabic quotations preserved inline. Retain/apply uses `output_contract=source_note_v2`: one proportional note, a hash-bound extraction receipt, and anchors on every retained Unit. Extraction and all other automated workflows never generate flash cards or recall drafts. New cards require an explicit learner-authored Arabic question and answer.
- Thread and Level completion derives only from direct lesson completion. Familiarity, utility, recall, and application may inform recommendations but never change progression.
- Explicit delivery context, adaptive depth, perspective diversity, frontier state, resurfacing, and note distillation may affect presentation or recommendation ranking only. Unknown context is neutral and Queue order remains canonical.
- Recommendation work is explicit-only. Resolve the active Thread and one intent, read `/compass/context`, check consumed/excluded/familiar sources, research current primary sources on the web, and submit 3–8 URL-anchored candidates with substantive editorial evidence. Save a basic intro for an already-used tool only as an ordinary captured Library source; reject corporate PR unless Mahmood explicitly wants it saved; allow a practical applied tool, major model release, or AI hardware analysis when it fits; reject low-level training-math theory. The Worker owns validation, deduplication, scoring, abstention, and receipts. Normal requests return one fit pick and wait for explicit Start. Books require `allow_books: true`. Bridge/challenge require explicit exploration.
- Islamic recommendations must be original lectures/khutbahs/talks by trusted Sunni scholars; no book-derived material. Respect all durable exclusions in `AGENTS.md` and the live profile.

Evidence-bearing checkpoints, deterministic validation, and atomic publication then bind that content to the pair.
