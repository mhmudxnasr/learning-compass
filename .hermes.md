# Learning Compass — Hermes Context

This repository is Mahmood's private Learning Compass learning operating system.

Read `AGENTS.md`, `PROJECT_CONTEXT.md`, and `CURRENT_STATE.md` before changing the project. They are the authoritative behavior, architecture, and handoff sources.

## Product

- Visual system: Scholar's Instrument.
- Loop: capture → curate → consume externally → reflect → notes → review → map update → resurface.
- D1 is canonical. R2 stores large artifacts. Obsidian is archive/export only for extracted notes.
- Seventeen real destinations are defined in `client/src/destinations.ts`; no fallback screens. Files, source-centric Notes, Recall, and Activity live together in Learn; Hermes operations and Memory Review live together in Insights; legacy routes redirect to merged destinations.

## Architecture

- Hono Cloudflare Worker in `src/`.
- Vite/Preact/TypeScript client in `client/`.
- Base schema: `schema.sql`.
- Migration order: `migrations/0000_brain.sql`, `migrations/0001_production_rebuild.sql`, `migrations/0002_rss_feeds.sql`, `migrations/0003_feedback_review.sql`, `migrations/0004_discovery_engine.sql`, `migrations/0005_recommendation_notebook_url.sql`, `migrations/0006_hermes_upgrade.sql`, `migrations/0007_sync_notifications.sql`, `migrations/0008_compass_cascade.sql`, then `migrations/0009_proposal_dedup.sql`.
- API contract: `docs/API.md`.

## Invariants

- All captures, including share target, Telegram, RSS, and Atom, land in unlimited Inbox. Enabled feeds refresh every six hours.
- Feed orchestration uses `~/.hermes/skills/productivity/rss-feed/SKILL.md`; user-requested refreshes send `{ "limit": 5 }`, paginate imported history, and never bypass Inbox triage.
- Archive keeps feed captures in a pinned RSS/Atom shelf; use `GET /recommendations/list?source=manual` when reporting the clean manual archive.
- Queue contains only queued/in-progress items and normally caps at five.
- Queue owns start, resume, and completion. Hidden sessions preserve linkage; `POST /sessions/:id/return` with `reflection`, `rating`, and `complete:true` closes the handoff and auto-creates the linked reflection note.
- Structured bilingual notes live on the site.
- Lite Visual resolves the exact source/pair, mines the complete source, builds a checksum-backed evidence packet and coverage matrix, and separates coverage from design passes.
- Lite Visual validates measured metadata, source anchors, responsive HTML, and the six-page PDF inspection set; HTML must score at least 8/10 with no factual/rendering defect.
- Lite Visual uploads a versioned linked HTML+PDF R2 pair with revision/supersession metadata and queues Notes Extractor from its HTML artifact only, exactly once; the extraction job and canonical source record must reach verified terminal state.
- `visualise_source` is enqueue-only from the Worker: its payload declares `custom_prompt_required`, `qa_required`, `quality_threshold: 8`, and expected `html`/`pdf` roles. Hermes owns source-specific prompting, mining, rendering, validation, upload, and completion. Artifact publication must satisfy the machine-readable HTML/PDF QA contract before release.
- Lite Visual PDFs use portrait-tablet typography: 15pt body text, readable supporting text, portrait-safe margins, and single-column print layouts even if that increases page count.
- A reflection supplied to Hermes is explicit feedback: `learning-compass-operating-system` preserves it verbatim in the canonical source record, queues exactly one Taste Mapper analysis, and waits for explicit approval in Learn → Activity before applying anything. If the source is untracked, capture it and create the completed source record first. It never follows feedback with a recommendation.
- Ratings 7–10 automatically queue Notes Extractor, which writes a complete bilingual English/Egyptian-Arabic source note covering the full source plus editable SRS drafts. User approval activates cards; drafts and approved cards remain deletable.
- Source notes expose a full bilingual re-run action when an older extraction is incomplete.
- Hermes defaults to OpenCode Zen's free-only failover chain: MiMo V2.5 Free, DeepSeek V4 Flash Free, Nemotron 3 Ultra Free, then other free Zen models. Paid models are prohibited.
- Handwritten PDF annotations are personal reflection data: preserve them with page anchors, flag uncertain OCR, and never merge printed source claims into the user's voice.
- Feedback never triggers a recommendation automatically.
- Personal Bayesian Cascade is the canonical recommendation workflow: keep at most one unresolved Compass Pick, submit 3 candidates first and expand only after a justified abstention up to 8, send structured metadata/evidence without scores, let the Worker own reachability checks, semantic deduplication, exclusions, D1-context ranking and calibrated confidence, expose one pick, and require explicit Start plus explicit feedback. `/discovery` and `/ai/suggest` remain compatibility/archive paths and never auto-chain a new recommendation.
- NotebookLM is the grounded knowledge corpus for Hermes. Use notebook `https://notebook.google.com/notebook/2c8a58a9-32b8-45db-804f-b48bf756e82c`.
- NotebookLM sync is feedback-driven and Hermes-controlled: when `taste-rec` recommends an item and Mahmood later gives explicit feedback, `taste-mapper` sends the complete relevant corpus update and feedback context to NotebookLM during that workflow. Do not create a background D1-to-NotebookLM sync job for every mutation.
- Send clean original source material and Mahmood's own reflections, notes, ratings, and feedback. Exclude generated Egyptian-Arabic translations, generated summaries, Lite Visual HTML/PDF companions, and any AI-written text unless Mahmood explicitly confirms it is his own thought. Use the original source URL/transcript/PDF/web text instead of Lite Visual output.
- NotebookLM queries must identify the role as Mahmood's grounded Taste Strategist and Chief Knowledge Officer, include the complete available relevant corpus, enforce all taste exclusions, cite exact source evidence, and flag contradictions. Studio generation is never automatic; explicit requests execute immediately. For a Learning Compass source-specific request, create a fresh per-source notebook, add the link as a Website source, start the requested artifact without downloading/uploading or waiting, and immediately save that notebook URL on the matching site item. Direct artifact requests may use the normal deduped wait/download flow.
- NotebookLM interactions use `PleasePrompto/notebooklm-mcp` (`notebooklm_*` MCP tools) as the primary engine and `teng-lin/notebooklm-py` as the direct Python API & CLI backup engine. Playwright DOM automation is completely removed.
- Hermes quality evidence is recorded in `recommendation_outcomes`; guarded memory is stored in `hermes_memory`; failed jobs use `agent_job_retries` with backoff, dead-letter alerts, and replay.
- Insights → Hermes is the operational control surface for queue health, prediction error, engine evidence, alerts, failures, and memory state.
- Insights → Hermes includes memory review: it searches, approves, rejects, expires, and inspects evidence for Hermes memories; source records expose `memory_influences`. `/analytics/hermes/weekly` reports evaluator signals and `/analytics/hermes/evaluate` creates pending proposals only. `/analytics/hermes/backfill` is dry-run by default and recalibration remains gated by five real rated outcomes. NotebookLM broker health is explicit through `/notebooklm/health` and `/notebooklm/recover`; stale or missing heartbeats are never reported as grounded.
- Hermes claims only the durable work created by an explicit Learning Compass request; there is no scheduled host poller and job operations are not shown in the site.
- Use one stable worker name for claim, heartbeat, complete, and fail calls. Keep `Mozilla/5.0 (compatible; HermesCron/1.0)` in the retained manual runner.
- E2E tests own and terminate Wrangler, Workerd, and Playwright processes.

## Hermes synchronization

### Procedural operating system

- `~/.hermes/skills/workflow/learning-compass-operating-system/SKILL.md` is the only entry point for Learning Compass chat. It classifies requests into reflection/feedback, session, capture/triage, recommendation, notes/artifact, proposal review, feed, job recovery, or product-operation procedures.
- The router calls one focused specialist after classification. `learning-compass-site-operator` executes the verified Worker API steps; specialist skills never infer a competing workflow.
- Reflection text is preserved verbatim through one `POST /feedback/record`. Numeric ratings mean completion unless explicitly provisional. The response is the canonical receipt for tracked and untracked sources.

### Agent control protocol

- Read `GET /agent/capabilities` before acting; it is the source of truth for methods and paths.
- Use `POST /agent/request` with `{method,path,body}`, or `/agent/tools` and `/agent/tool-call` for function-calling clients.
- Send `x-agent-name` for audit attribution and `x-api-token` for authenticated writes.
- Never guess routes, use arbitrary SQL, or use an external proxy. Preserve queue, SRS, D1/R2, feedback, and Lite Visual invariants.

When product API, schema, algorithm, or workflow contracts change, update:

- `~/.hermes/skills/workflow/recommendations-worker-ops/SKILL.md`
- `~/.hermes/skills/workflow/learning-compass-operating-system/SKILL.md`
- `~/.hermes/skills/workflow/learning-compass-site-operator/SKILL.md`
- `~/.hermes/skills/taste-mapper/SKILL.md`
- `~/.hermes/skills/personal/taste-rec/SKILL.md`
- `~/.hermes/skills/taste-enhancer/SKILL.md`
- any other active skill that references the changed contract
- durable rules in `~/.hermes/memories/MEMORY.md` or `USER.md` only when the change is a durable user/workflow rule

Do not restore the deleted template-string frontend, `schema_v2.sql`, or obsolete artifact scripts.
After a material change, update `CURRENT_STATE.md`; update `PROJECT_CONTEXT.md` only when a stable contract changes.
