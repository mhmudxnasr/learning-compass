## Non-negotiable behavior

- Every capture becomes a `captured` Library record with its validated non-pruned branch persisted in the same write. Before completion, reread that branch plus round. Queue normally has at most five queued/in-progress items; overflow needs explicit override.
- Consumption happens at the real source and is tracked through sessions.
- Preserve raw feedback verbatim through exactly one `POST /feedback/record`; it owns tracked and untracked feedback plus completion, so never duplicate the reflection with `POST /sessions/:id/return`. Record the shared structured envelope (`completion_state`, `reason_tags`, `expected`, `actual`, `effort`, `length_minutes`) alongside the separate rating and `retain|apply|reference|drop` disposition. `in_progress`/`not_now` is neutral; `stopped` requires a reason. Verify the returned receipt and the source dossier. Feedback never triggers another recommendation.
- Source synthesis is English-first for Mahmood, with original Arabic quotations preserved inline. Retain/apply uses `output_contract=source_note_v2`: one proportional note, a hash-bound extraction receipt, and anchors on every retained Unit. Extraction and all other automated workflows never generate flash cards or recall drafts. New cards require an explicit learner-authored Arabic question and answer.
- Thread and Level completion derives only from direct lesson completion. Familiarity, utility, recall, and application may inform recommendations but never change progression.
- Explicit delivery context, adaptive depth, perspective diversity, frontier state, resurfacing, and note distillation may affect presentation or recommendation ranking only. Unknown context is neutral and Queue order remains canonical.
- Recommendation work is explicit-only. Resolve the active Thread and one intent, read `/compass/context`, check consumed/excluded/familiar sources, research current primary sources on the web, and submit 3–8 URL-anchored candidates with substantive editorial evidence. Save a basic intro for an already-used tool only as an ordinary captured Library source; reject corporate PR unless Mahmood explicitly wants it saved; allow a practical applied tool, major model release, or AI hardware analysis when it fits; reject low-level training-math theory. The Worker owns validation, deduplication, scoring, abstention, and receipts. Normal requests return one fit pick and wait for explicit Start. Books require `allow_books: true`. Bridge/challenge require explicit exploration.
- Islamic recommendations must be original lectures/khutbahs/talks by trusted Sunni scholars; no book-derived material. Respect all durable exclusions in `AGENTS.md` and the live profile.
- Lite Visual creates one atomic HTML+PDF pair, or one pair per book chapter. The semantic Arabic HTML article is the only canonical reading body and the A4 PDF is printed from it. Acquire the body only through `lite-visual/scripts/extract_source.py`; its hash-verified cache and source-specific adapters emit `lite-visual-source-extraction/v1`, and `map_coverage` is blocked until that receipt is complete. Preserve every important argument, example, mechanism, caveat, and conclusion while labeling added clarification. The workflow is linear and code-only: semantic HTML, source-specific CSS, native structures, and rare justified inline SVG. It has no templates, stored palettes, preset themes, mind maps, raster/generated images, external image-agent calls, scripts, widgets, mandatory pauses, scores, streaks, XP, or second progress system. Gapless source scopes, a claim-level coverage ledger, evidence-bearing checkpoints, deterministic validation, and atomic publication are mandatory. `run_workflow.py` owns the standard extraction/render/validate/publish path and optional job lease lifecycle. There is no subjective QA score and no automatic Notes Extractor chain.
- YouTube transcript mining for visual work is Arabic-first: use the shared `fetch_transcript.py` adapter with `ar,ar-SA,ar-EG,en` priority. English is fallback-only when Arabic is genuinely unavailable. Never use `YouTubeTranscriptApi.fetch()`'s default English-only language list, and never treat an Arabic transcript as an adapter failure.
- NotebookLM uses only original source material and Mahmood-authored reflections/notes for corpus grounding. Generated summaries, translations, and companions are not his voice. For explicit source learning, require the exact saved notebook and indexed-source receipt, route one focused plan (hard quiz by default, at most three concept-fit outputs), and record indexed/pending/ready/failed provider receipts. A link is not indexed and a pending artifact is not ready. Do not create background Studio work or change lesson progress/mastery from a generated artifact.
- Notes Extractor optimizes for four-year retrieval: precise English source claims plus concise natural Egyptian-Arabic explanation in separate blocks, with Misconception vs. Truth and complete study/experiment coverage when supported. Handwriting remains verbatim in native blocks without Obsidian syntax. Never create Obsidian archive copies for books or book chapters.
- No scheduled learning-core poller, autonomous recommendation, routine self-improvement message, or background media generation.
- Self-evolution is conversation-bound. Specialists emit evidence, not self-edits. Only `learning-compass-self-evolution` may accept a concrete improvement candidate after replay/tests. No evidence means no change and no database churn. Destructive deletion and external publication remain explicit-only.
- When a concrete tool, adapter, prompt, or workflow failure is observed, `learning-compass-self-evolution` must capture the exact error, reproduce it, repair the narrowest owning layer, add a regression test/validator, replay the original path, and write scoped `skill_procedure` evidence. A reproducible repairable failure cannot be closed as `no_change`; blocked repairs close as `failed` with a resumable next step.
- Raw transcript/source material is a separate evidence artifact and may never appear hidden or collapsed inside the HTML/PDF. `source-scope.json` must partition every normalized word in the checksum-matched `source.txt` with no gap or overlap; `coverage-ledger.json` must bind exact source anchors in every scope and every declared numbered item to exact visible HTML anchors.
- Before authoring, read the current Intent and Frontend Design skills. Derive typography, colors, rhythm, and one restrained signature from the source itself; never store or reuse a theme, palette, template, layout preset, or style lock.
- The deterministic v5 gate checks canonical identity, gapless coverage, claim traceability, Arabic RTL semantics, accessibility, code-only markup, responsive geometry at 360/768/1280px plus 200% text size, A4 size and non-empty text on every PDF page, and HTML/PDF text parity. It emits one hash-bound receipt and never creates screenshots or uses a vision model.
- Publish only through atomic `POST /artifacts/pairs`; generic single-file Lite Visual uploads are invalid. On failure publish nothing and keep cached evidence. Resume a current v4 job only from a declared `workflow_step`; upgrade a legacy or malformed payload to v4 and restart it at `resolve_source`.
- Never expose credentials or secrets. Keep private/local network access deny-by-default unless the operator procedure explicitly authorizes a known Learning Compass service.
