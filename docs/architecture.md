# Architecture

The machine-readable Hermes contract in [`docs/hermes-contract.json`](./hermes-contract.json) is canonical for workflow ownership, endpoint permissions, side-effect tiers, and policy routing. This document explains the implementation; it must not redefine those rules.

The Worker owns API routes and explicit durable work. The Vite/Preact client is a static asset bundle served through the Worker’s Assets binding. D1 stores relational state and structured notes; R2 stores large source artifacts. The client uses hash routes so the Worker remains a single-page shell.

Hermes processes only the exact durable work created or exposed by an explicit conversation. Extraction jobs run `learning-notes-extractor`; feedback analysis runs `taste-mapper`. Analysis jobs persist reviewable `feedback_proposals`. Evidence-qualified profile, map, and scoring changes may be applied automatically when the canonical contract's evidence threshold is met. A verified skill failure or better path may also be saved as narrowly scoped, reversible `hermes_memory` procedure knowledge after replay/test validation; editing skill source remains proposal-only. Code, schema, and runtime changes remain proposal-only; deployment, destructive deletion, and external publication remain explicit-only. The worker is idempotent through job keys, leases, and bounded retries. D1 writes happen before Obsidian archive copies.

Hermes operational state is explicit: `recommendation_outcomes` stores prediction and outcome evidence, `hermes_memory` stores typed provenance-backed memories with evidence, approval, expiry, and supersession, `creator_trust` stores backfilled creator feedback, `agent_job_retries` stores delayed retry/dead-letter state, and `hermes_alerts` stores actionable failures. Insights → Hermes reads these tables through `/analytics/hermes`; the weekly evaluator creates pending proposals only, while weight recalibration is explicit, requires at least five rated discovery outcomes, and remains bounded to protect against overfitting.

NotebookLM is a Hermes-controlled grounding service, not a D1 replication target. The Worker exposes a broker heartbeat/recovery receipt protocol at `/notebooklm/health` and `/notebooklm/recover`; it reports `grounded`, `fallback`, or `offline` explicitly and never fabricates corpus statistics or claims to own the local browser session. During explicit feedback on a recommendation, Hermes sends the complete relevant corpus context to the saved Master Corpus notebook, using original source material and Mahmood-authored reflections/feedback. Generated translations, generated summaries, and Lite Visual HTML/PDF companions are excluded as personal thoughts. No background job is created for every D1 mutation, and Studio artifacts are generated only after an explicit chat request. For a source-specific Studio request, Hermes creates a fresh NotebookLM notebook, inserts the public source URL, starts the artifact without downloading/uploading or waiting, and immediately stores the new notebook URL on the matching site recommendation. Grounded Q&A uses the pinned NotebookLM MCP server: compatible investigations reuse MCP sessions, while topic changes, low-confidence matches, idle expiry, or session failure start a new session. Exact answers are cached for 24 hours only with notebook, normalized question, prompt version, and corpus fingerprint in the key.

RSS and Atom subscriptions are stored in `feed_sources`; imported GUIDs link to Inbox recommendations through `feed_entries`. The Worker checks enabled feeds on its six-hour schedule, uses conditional HTTP headers, caps each response at 2 MB and 20 entries, and rejects private/local URLs and unsafe redirect targets.

The client uses route-level data contracts, IndexedDB for offline mutation queuing, local storage for preferences and session state, and a cache-busting service worker. Atlas is a lazy-loaded Cytoscape canvas boundary: it derives clusters from the canonical graph response, starts with major R1 branches, and progressively expands descendants without adding graph code to the base client bundle. `/learning/balance` is the shared read model for Coverage and Hermes: it resolves source activity onto the tree, rolls metrics through R1/R2/R3 ancestry, combines attention share with explicit priorities and retention evidence, and keeps unmapped sources visible instead of silently assigning them.
