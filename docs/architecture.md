# Architecture

Learning Compass is one Cloudflare Worker application with a statically built Preact client. D1 is the canonical relational store, R2 owns large artifacts, and Hermes performs bounded background work through the public Worker contract. There is no second backend or client-side database of record.

## Runtime flow

```text
Browser / installed PWA / capture extension
                  |
                  | HTTPS and hash-route navigation
                  v
        Hono Cloudflare Worker (`src/`)
             |                 |
             | SQL             | object reads/writes
             v                 v
             D1                R2
             ^
             | allow-listed, leased API jobs
             |
           Hermes
```

The Worker serves the built client from its Assets binding. The client reaches domain state only through HTTP helpers in `client/src/api.ts`. Hermes also uses the Worker API and never writes D1 or R2 directly. The browser extension opens the normal capture route; it does not have a separate ingestion API.

## Module ownership

- `client/src/app/` owns startup, top-level composition, and route registration. `client/index.html` loads `client/src/app/entry.tsx` directly.
- `client/src/shell/` owns cross-workspace navigation and command surfaces. `client/src/workspaces/` owns destination screens; `client/src/features/` contains reusable bounded features such as Atlas and Branches.
- `client/src/styles/` divides the application cascade by product area. `client/src/studio.css` imports those modules in a fixed order, and the directory README documents placement rules.
- `src/index.ts` is the Worker composition root. `src/api/` translates HTTP to typed application calls; `src/services/` owns reusable workflows and persistence orchestration; `src/domain.ts` and focused helpers own pure business rules.
- `schema.sql` is the base local schema. `migrations/` is the only production schema evolution path; migrations are numbered, ordered, and idempotent.
- `scripts/` owns operator commands. `tests/unit/`, `tests/integration/`, and `tests/e2e/` cover pure contracts, isolated Worker/D1 flows, and browser-visible behavior respectively.
- `docs/API.md` is the HTTP contract, `PROJECT_CONTEXT.md` is the durable product contract, `CURRENT_STATE.md` records verified operational truth, and `CHANGELOG.md` records why the repository changed.

Dependencies point inward: workspace views may use features and the shared API client; API routes may use services and domain helpers. Domain/service code cannot import the client, features cannot own global routing, and Hermes cannot bypass the Worker. A change that crosses one of these boundaries must update both contracts and boundary tests.

## Request and data boundaries

1. The client validates interaction state and sends a typed request through `client/src/api.ts`.
2. A route in `src/api/` validates untrusted input, applies transport policy, and calls the owning service or domain function.
3. The service performs one bounded D1/R2 operation or creates an idempotent leased job. Domain invariants remain server-owned even when the client mirrors them for usability.
4. The route returns a stable client-safe response. Retried mutations use stable IDs or idempotency keys, and the client keeps offline mutations in IndexedDB until confirmed.
5. Hermes claims only allow-listed work, writes through the same Worker validation path, and verifies canonical readback before treating a mutation as complete.

Anchored `unit_relations` are the canonical semantic-link layer for meaningful backlinks, cross-branch bridges, and contradiction review; bridges are derived and never duplicated into a synthetic graph. Note distillation is additive D1 state above immutable canonical note sections. Resurfacing state is recommendation-backed and branch-validated. Delivery context, adaptive depth, perspective diversity, and knowledge-frontier states are advisory read/scoring models and cannot mutate lesson progression.

## Learning core

D1 keeps canonical Learning Threads, reusable sources, anchored Learning Units, direct lesson status, source outcomes, and derived recommendation signals. `consolidation_runs` plus ordered steps correlate explicit source dispositions with Hermes jobs and expose terminal user state without exposing infrastructure controls. Hermes owns exact-job execution during the active conversation that created or exposed the work. No poller, timer, scheduled consolidation, or scheduled self-improvement exists. Thread and Level progression derives only from direct lesson completion.

`personal_library_items` is a typed extension of canonical `recommendations`, not a second media database or a Queue projection. It owns personal media type, lifecycle state, release/duration/progress, tags, note, and start/completion timestamps; canonical title/creator/URL/rating and verified `recommendation_meta.branch_id` remain shared. URL-free identity is deterministic by normalized type/title/creator, URL identity uses the existing canonical dedup path, and `learning_events` records import/create/update lineage. Book intake, reading-state changes, and chapter-progress changes synchronize the same row and edit activity. Personal status never mutates source lifecycle, starts a session, or advances a lesson.

Recommendation list and branch-ledger reads select the bounded parent rows first, then enrich only those recommendation IDs in batches of at most 75. Notes use their recommendation index, artifacts use the recommendation expression index, and recall counts use `idx_srs_cards_recommendation_due`; list reads must not restore per-row correlated metadata scans.

Broad navigation search uses the derived ordinary `search_idx` table keyed by `(source,ref_id)`. Six-hour maintenance replaces its bounded source/node/Unit/note/assertion/memory/annotation rows, while capture paths update source rows immediately. Search accepts a capped query and uses an escaped substring match with a 16-row projection limit. Migration `0067_portable_search_and_lineage_repair.sql` removes the invalid self-referential FTS5 virtual table so maintenance deletes and portable D1 exports can succeed; a compatibility-only column and no-op trigger accept the immediately previous Worker's legacy `optimize` command during a code rollback. The migration also nulls only historical `learning_events.thread_id` pointers whose Thread no longer exists, matching the canonical Thread-deletion transaction without deleting or rewriting the event itself.

Every non-static Worker request atomically reserves a conservative estimated D1 cost in `free_tier_usage_budget` before route execution. The UTC-day circuit breaker stops reads at 4,000,000 estimated rows and writes at 70,000 estimated rows, leaving fixed 1,000,000-read and 30,000-write margins below Cloudflare's 5,000,000/100,000 free limits; exhausted requests return `429` until midnight UTC. `/health/free-tier-budget` exposes the ledger, provider limits, margins, and policy result without consuming that budget. `npm run verify:budget` makes reduced headroom a release-gate failure.

Legacy source, note, map, SRS, and REST identifiers remain readable during additive migration. No legacy rating or `mastered` row is silently converted into verified mastery.

Recall uses FSRS-6 through the official `ts-fsrs` package. D1 persists difficulty, stability, lapses, learning steps, scheduled days, state, due date, and scheduler version per card; legacy cards and their review history are migrated without deletion.

The machine-readable Hermes contract in [`docs/hermes-contract.json`](./hermes-contract.json) is canonical for workflow ownership, endpoint permissions, side-effect tiers, and policy routing. This document explains the implementation; it must not redefine those rules.

Hermes reaches the owned site through the bounded first-party `site_request.py` client and the allow-listed Worker API, not an MCP subprocess or raw D1 access. Ordinary Learning Compass reads and writes are public at the transport layer; the installed client contains no Learning Compass credential-file, credential-header, or browser-session path, and retired `POST /auth/session` returns 404. Telegram and external providers retain their dedicated secret boundaries. Open-ended manager work reads the deterministic briefing once; known work reads its narrow target; broader context is loaded only when several live domains affect a decision. Static SOUL/USER/MEMORY state is bounded durable context, while current Queue, jobs, progress, and blockers always come from live Worker reads. Possibly committed mutations stay reserved and require one canonical reread before retry. The operational lifecycle, prompt budgets, failure matrix, job recovery, gateway reload, SLOs, and rollback gate are defined in [`docs/hermes-production.md`](./hermes-production.md).

The Worker owns API routes and explicit durable work. The Vite/Preact client is a static asset bundle served through the Worker’s Assets binding. D1 stores relational state and structured notes; R2 stores large source artifacts. The client uses hash routes so the Worker remains a single-page shell.

Hermes processes only the exact durable work created or exposed by an active conversation. Extraction jobs run `learning-notes-extractor`; feedback analysis runs `taste-mapper`. Every specialist ends with a compact evolution handoff, and `learning-compass-self-evolution` is the single owner that deduplicates evidence and chooses whether to change anything. Profile proposals are typed, versioned, and reversible: Hermes applies a normal change at confidence ≥0.8 with a direct user statement or two evidence items; superseding an explicit user assertion requires a direct contradiction or confidence ≥0.95 with three evidence items. Lower-confidence hypotheses remain pending. Verified narrow skill, prompt, code, test, additive-schema, and workflow improvements may apply after replay and full verification, with Hermes editing directly unless Mahmood explicitly requests an external agent; deployment remains gated by release checks, a rollback version, and live smoke. Validated reversible workarounds may also persist as scoped skill-procedure memory. Broad or insufficiently verified changes remain proposal-only. Evaluated candidates close as applied, deployed, failed/resumable, reverted, or evidence-backed no-change receipts; no candidate creates no D1 churn. There is no scheduled/background self-improvement. Destructive deletion and external publication remain explicit-only. The Worker remains idempotent through job keys, leases, and bounded retries.

Recommendation intelligence uses immutable `learning_events` as the signal ledger and `recommendation_outcomes` as a REST-compatible projection. Administrative exclusion, neutral dismissal, explicit bad fit, rating, learning disposition, completion, and later evidence have separate event types and scopes. `learning_value_v2` combines available rating (25%), explicit retain/apply/reference/drop disposition (25%), and strongest recall/explanation/transfer/application/decision/artifact evidence (50%) without treating missing components as zero. Only explicit utility data enters training cohorts; bad-fit eligibility events can tune fit after the evidence gate, while `not_now` never penalizes a source.

Compass v2 is Thread-first. Each researched set covers fit, bridge, and challenge lanes, requires structured source evidence, canonicalizes format and creator aliases, and scores Thread contribution alongside relevance, source quality, information gain, novelty, format fit, and evidence quality. Shadow mode stores v1 and v2 decisions together. Activation requires 20 global learning-value outcomes, eight in every lane, at least ten shadow decisions, and zero invalid-evidence winners; rollback restores shadow mode. Weight deltas remain bounded to ±0.01 per observation and ±20% of baseline.

Hermes operational state is explicit: typed profile state lives in `profile_assertions` plus append-only `profile_assertion_revisions`; recommendation repair uses a source-clock snapshot and `self_improvement_runs`; `hermes_memory` keeps provenance-backed memories; `agent_job_retries` and `hermes_alerts` keep recovery state. Mutating evaluator, repair, backfill, and recalibration calls require an active conversation identifier and write a receipt. Insights → Hermes reads clean cohorts through `/analytics/hermes`. The weekly evaluator is on-demand compatibility only, never scheduled, and recalibration requires at least 20 training-eligible v2 outcomes.

NotebookLM is a Hermes-controlled grounding service, not a D1 replication target. The Worker exposes a broker heartbeat/recovery protocol at `/notebooklm/health` and `/notebooklm/recover`; it reports `grounded`, `fallback`, or `offline` explicitly and never fabricates corpus statistics or claims to own the local provider session. During explicit feedback on a recommendation, Hermes sends the complete relevant corpus context to the saved Master Corpus notebook, using original source material and Mahmood-authored reflections/feedback. Generated translations, summaries, and Lite Visual companions are excluded as personal thoughts. No background job is created for D1 mutations, and Studio work starts only after an explicit request. For source learning, `/notebooklm/learning/route` requires the exact saved notebook URL and an indexed-source receipt, defaults to one hard source-grounded quiz, permits concept-fit media only, and caps the plan at three outputs. `/notebooklm/learning/receipts` records source `pending|indexed|failed` and artifact `pending|ready|failed` in the existing receipt ledger; ready claims must satisfy the selected output contract and never change lesson, Level, or Thread completion or recall scheduling. Grounded Q&A uses the installed NotebookLM CLI; provider truth remains separate from Worker state and no NotebookLM MCP schema is loaded into Hermes.

RSS and Atom subscriptions are stored in `feed_sources` with one D1-enforced, reviewed, non-pruned default branch; imported GUIDs link to captured Library sources through `feed_entries`, and every newly created source inherits that branch plus mapping provenance in the same capture path. Canonical deduplication preserves an existing reviewed source mapping and reports `branch_conflicts` rather than silently changing it. The Worker checks enabled feeds on its six-hour schedule, uses conditional HTTP headers, caps each response at 2 MB and 20 entries, and rejects private/local URLs and unsafe redirect targets.

Migration `0077_feed_entry_dismissals.sql` adds `feed_entry_dismissals`, keyed by feed and recommendation with cascading ownership references. Skip inserts only this receipt; it retains `feed_entries` and its GUID so synchronization cannot reimport the dismissed entry. Feed queries and totals omit matching receipts. The split reader updates its local list immediately, restores failed writes, and uses online-only dismissal requests to avoid ambiguous offline removal. It loads all paginated results rather than silently limiting navigation to the first 50 articles.

`/agent/system.data_quality` is the user-visible data contract projection. It checks active-source identity, non-pruned taxonomy coverage, canonical uniqueness, learning-event ownership lineage, and enabled-feed branch defaults and reports exact affected counts and coverage. It deliberately exposes named checks rather than collapsing trust into an opaque engagement or “AI quality” score. The separate `/capture/personal` summary powers descriptive type/state/activity/branch visuals from exact D1 counts; those visuals likewise have no composite score.

The client uses route-level data contracts, IndexedDB for offline mutation queuing, local storage for preferences and session state, and a registered cache-busting service worker. Its Android PWA manifest is the single mobile application contract: standalone launch, adaptive launcher assets, launcher shortcuts, and Android share-to-Library all resolve into the same five-root client. The service worker precaches the fingerprinted public application shell and uses bounded network-first fallback caching without an authentication namespace; activation purges the retired pre-auth data namespace. Mutation recovery remains owned by IndexedDB. Successful HTML artifact navigations are stored automatically in a separately versioned exact-URL cache and refreshed network-first, so an opened companion remains readable offline without allowing artifact HTML to poison the application-shell cache. PDFs and unopened companions remain network-dependent. Explicit offline packs are separate versioned caches: each holds complete verified companion pairs and a compact revision-hashed snapshot of its already-loaded source/book/Thread owner, validates server-returned pair/role/publication/validation metadata during the actual fetch, and switches its manifest only after every new response is cached. Lesson sources expose one material launcher: the stored recommended medium when available, otherwise HTML then Original, with purpose-labelled alternatives and real file/provider state. The Thread path selects a complete HTML/PDF pair by pair ID and revision and batches NotebookLM receipt reduction per source, so the client never mixes companion revisions or calls a mere notebook link “ready.” A Play Store package must be a verified Trusted Web Activity over this origin, not a second WebView codebase. Atlas is a lazy-loaded Cytoscape canvas boundary: it derives clusters from the canonical graph response, groups by top-level domains and branches, and progressively expands descendants without adding graph code to the base client bundle. `/learning/balance` is the shared read model for Coverage and Hermes: it resolves source activity onto the tree, rolls metrics through tree ancestry, combines attention share with explicit priorities and retention evidence, and keeps unmapped sources visible instead of silently assigning them.

`share_intakes` is the durable redirect boundary for Android/web shares. A valid form body is inserted before the Worker emits a client redirect, and pending receipts are recoverable by exact ID or newest-first listing. A URL accompanied by distinct prose is stored as `review`, not inferred to be an anchor; `resolved_kind` durably records the learner's explicit whole-source or selected-passage choice and rejects a conflicting stale-tab choice. Exact passage text over 10,000 characters is rejected rather than truncated. The receipt persists normalized URL and dedup identity, while annotations persist derived normalized selector identities. Recovery and consumption can therefore follow verified URL-replacement lineage and ignore fragments/tracking noise without allowing a same-quote anchor from another source. The intake itself is not a source. Capture/anchor target validation and consumption share one conditional D1 update, including non-deleted canonical source, exact annotation, annotation-to-source branch equality, and non-pruned branch/domain predicates. This keeps app-close recovery and idempotent completion without introducing a branchless Library record or a validation/write race.

Branches are the primary organizing axis across the product: the Queue, the Branch Deck, the linked-items ledger (`/brain/branches/:id/items`), and the unified source dossier all surface the same canonical branch identity, priority, status, and domain. The taxonomy follows a clean 3-tier structure: Super Category (Domain) → Knowledge Branch (`tree_nodes`) → Topics/Leaves (`meta_json.leaves`). Synthetic round tags (`[R1]`, `[R2]`, `[R3]`) are retired: active services do not derive them, API and sync projections strip historical fields, and the client does not render or search them. Historical schema columns, migration names, and bracket-label cleanup remain inert compatibility only. The canonical branch linkage is `recommendation_meta.branch_id` with dedup-key prefix resolution as the legacy fallback.

Books is composed as the first Library workspace while keeping two bounded data models. My books reads captured `recommendations` book records and book-scoped chapter/artifact projections; Canon fields use `canon_atlases`, `canon_domains`, `canon_entries`, and `canon_entry_revisions` because an evergreen domain atlas does not share Thread progression or the captured-source lifecycle. Database uniqueness and completion triggers protect the trio invariant. Explicit Canon capture uses the normal captured-source deduplication path, persists the domain branch, and projects `canon_memberships[]` onto the same book identity in list and dossier reads. Manual book intake likewise requires an existing non-pruned branch and atomically persists the branch and domain. Legacy Learn Books and Shelf/Atlas focus URLs canonicalize to the Library Books route.
