# Architecture

The Worker owns API routes and scheduled intelligence. The Vite/Preact client is a static asset bundle served through the Worker’s Assets binding. D1 stores relational state and structured notes; R2 stores large source artifacts. The client uses hash routes so the Worker remains a single-page shell.

Hermes polls D1 jobs every two minutes. Extraction jobs run `learning-notes-extractor`; feedback analysis and approved-proposal application run `taste-mapper`. Analysis jobs must persist reviewable `feedback_proposals` without mutating intelligence state. Only user approval queues the exact application job. The worker is idempotent through job keys, leases, and bounded retries. D1 writes happen before Obsidian archive copies.

NotebookLM is a Hermes-controlled grounding service, not a D1 replication target. During explicit feedback on a recommendation, Hermes sends the complete relevant corpus context to the saved Master Corpus notebook, using original source material and Mahmood-authored reflections/feedback. Generated translations, generated summaries, and Lite Visual HTML/PDF companions are excluded as personal thoughts. No background job is created for every D1 mutation, and Studio artifacts are generated only after an explicit chat request. For a source-specific Studio request, Hermes creates a fresh NotebookLM notebook, inserts the public source URL, starts the artifact without downloading/uploading or waiting, and immediately stores the new notebook URL on the matching site recommendation. Grounded Q&A uses the local NotebookLM broker: compatible investigations reuse a warm authenticated browser session, while topic changes, low-confidence matches, idle expiry, or browser failure start a new session. Exact answers are cached for 24 hours only with notebook, normalized question, prompt version, and corpus fingerprint in the key.

RSS and Atom subscriptions are stored in `feed_sources`; imported GUIDs link to Inbox recommendations through `feed_entries`. The Worker checks enabled feeds on its six-hour schedule, uses conditional HTTP headers, caps each response at 2 MB and 20 entries, and rejects private/local URLs and unsafe redirect targets.

The client uses route-level data contracts, IndexedDB for offline mutation queuing, local storage for preferences and session state, and a cache-busting service worker. Atlas is a lazy-loaded Cytoscape canvas boundary: it derives clusters from the canonical graph response, starts with major R1 branches, and progressively expands descendants without adding graph code to the base client bundle.
