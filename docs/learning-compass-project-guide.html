01 · Thesis

Learning Compass is a learning operating system.

It turns scattered sources into a repeatable loop: define what matters, select useful material, consume it at the real source, reflect, consolidate what was learned, retrieve it later, and use evidence to decide what should resurface.

The core distinction: a source is an input, not proof of learning. Learning becomes real when a Thread has anchored units and evidence of retrieval, explanation, transfer, decision, creation, or application.

Product

Purpose before volume

Learning Threads hold the question, urgency, definition of done, evidence requirements, and source roles. The system is organized around decisions and capabilities, not an endless content list.

Intelligence

Evidence before adaptation

Ratings, fit labels, dispositions, completion, retrieval, and transfer stay separate. Recommendation and profile changes only use the signals they can honestly support.

Operating style

Explicit, reversible, auditable

Hermes can act inside an explicit workflow, but consequential changes carry receipts, confidence, provenance, validation, and an undo or rollback path.

02 · Learning loop

Capture → curate → consume → reflect → consolidate → retrieve → resurface.

DefineOpen or refine a Learning Thread.
CapturePut URL, text, PDF, HTML, video, book, Telegram, share-target, RSS, or Atom input in Inbox.
CurateQueue a source when it fits the current purpose and cap.
ConsumeStart the real source and track the learning session.
ReflectReturn with a verbatim personal reflection and structured feedback.
VerifyExtract units, retrieve, apply, and resurface evidence.

Every capture enters the unlimited Inbox. The active Queue normally holds at most five queued or in-progress items. Queue overflow needs an explicit override. Starting, returning, and completing a source remain explicit actions.

Feedback stops the loop before recommendation. Processing a reflection can update proposals, the map, or profile evidence, but it never silently requests another recommendation.

03 · Architecture

One canonical product, clear storage boundaries.

Client

Vite + Preact + TypeScript

The browser provides the Scholar's Instrument interface: compact, typographic, neutral, precise, responsive, and centered on the learning loop. The route registry contains five root destinations, 11 grouped modes, and subordinate focus filters.

Worker

Hono on Cloudflare Workers

src/index.ts owns routing, rate limits, write protection, request receipts, scheduled product maintenance, API composition, and the D1/R2 bindings.

D1

Canonical structured state

Recommendations, captures, sessions, Threads, Learning Units, notes, ratings, SRS cards, map data, settings, feedback, memory provenance, jobs, and improvement receipts live here.

R2

Large artifacts

HTML, PDF, transcripts, and generated companions live in the taste-map-artifacts bucket. D1 keeps their identity, source relationship, role, checksum, and metadata.

Hermes

Explicit workflow executor

Hermes reads the product through the allow-listed agent API, claims only the work created by the active workflow, runs one focused specialist, verifies the result, and records a receipt.

Archive

Obsidian is a one-way note export

Obsidian receives extracted notes only. It is not a second canonical database and must never overwrite D1.

05 · Learning model

Learning is a graph of purpose, claims, and evidence.

Learning Threads

A Thread is the purpose-first container for one question, decision, build, or capability. It has a guiding question, definition of done, evidence requirements, source roles, a final synthesis, and a verified state.

Learning Units

Units are atomic claims, concepts, methods, examples, questions, applications, and counterclaims. Each unit carries exact source anchors, personal synthesis, stance, confidence, and typed relations.

Mastery

Taste rating is not mastery. Verified mastery comes from retrieval, explanation, transfer, decision, artifact, or application evidence. A completed source can be enjoyable without being retained.

Recall

Approved SRS drafts become cards. FSRS-6 schedules the cards through the official ts-fsrs implementation. A failed review never advances mastery.

Consolidation

Explicit completion can create a durable consolidation run with a visible terminal state: closed, repair required, or waived. There is no hidden learning-core timer.

Map and balance

Atlas stores branches, edges, evidence, contradictions, coverage, health, and attention. Learning Balance is the shared read model for the site and Hermes.

Notes are projections, not the whole knowledge model. The Notes library is the readable extracted view. The source record still links the original source, personal feedback, sessions, artifacts, units, evidence, recall, and memory influence.

06 · Recommendations

Compass chooses the next useful source under evidence and constraint.

The current recommendation path is Thread-first and shadow-scored. It looks at the active purpose, source reachability, duplicates, mastered and consumed sources, typed profile assertions, creator and format utility, learning balance, branch contribution, evidence quality, and exploration lanes.

Fit

Does this serve the Thread?

Fit candidates advance the current goal directly and satisfy its source role.

Bridge

Does this connect fields?

Bridge candidates add a useful adjacent concept without drifting into generic novelty.

Challenge

Does this test a belief?

Challenge candidates create productive counter-evidence and expose weak assumptions.

Serving rules

  • Recommendations happen only on an explicit request.
  • Normal requests expose one strong pick and wait for explicit Start.
  • Explicit Queue-fill requests can run bounded waves and start only Worker-returned ready picks.
  • A withheld weak pick needs its own exact Add to Queue anyway override.
  • The five-item Queue cap still applies unless the user explicitly overrides it.
  • Not now is neutral. Bad fit is a reasoned eligibility signal. Administrative exclusion is not negative taste.
  • Consumed and mastered sources are checked before anything is proposed.

Evidence gates

Compass V2 remains shadow until it has 20 clean global learning-value outcomes, eight per lane, ten shadow decisions, and zero invalid-evidence winners. Adaptation stays bounded while evidence is thin.

The learning-value signal combines available rating (25%), explicit disposition (25%), and strongest retrieval/transfer/application evidence (50%). Missing components are not silently treated as zero.

07 · Hermes

Hermes is the procedural operating system; self-evolution has one owner.

The router classifies every Learning Compass request into one verified procedure, calls one focused specialist, and ends with one compact evolution handoff. Specialists do not independently rewrite the system.

learning-compass-operating-system

Routes every request, preserves the product loop, prevents feedback from auto-recommending, and sends one end-of-turn evolution handoff.

learning-compass-self-evolution

The sole owner for evidence deduplication, thresholds, profile/procedure/system candidates, skill graph health, rollout decisions, receipts, rollback, and no-change decisions.

learning-compass-site-operator

Reads before writes through the allow-listed Worker API, uses the Hermes User-Agent, verifies after mutations, and reports the canonical receipt.

recommendations-worker-ops

Owns health, migrations, deployment gates, live smoke, job recovery, release receipts, and operational failure handling.

taste-mapper

Processes explicit feedback into typed profile, map, creator, format, or scoring proposals with evidence and confidence.

taste-rec

Runs explicit recommendation work, reads the full context, applies exclusions and deduplication, and returns a bounded Compass pick.

learning-notes-extractor

Turns an explicit source or artifact into structured, editable, bilingual-aware notes. It never runs automatically after Lite Visual.

lite-visual

Creates source-grounded HTML/PDF reading companions, complete evidence packets, checksum metadata, and canonical artifact verification.

visual-mind

Plans source-proportional diagrams, tables, images, and other visual assets with provenance and deterministic fallback behavior.

notebooklm

Handles grounded corpus Q&A and explicit Studio requests through the native NotebookLM MCP workflow and its direct API backup.

rss-feed

Subscribes, refreshes, paginates, and reports RSS/Atom sources. Feed items still enter Inbox and do not bypass triage.

agent-cli-delegation

Delegates repository edits and verification to Codex while preserving scope, evidence, and release boundaries.

youtube-playlist-verification

Verifies playlist sources and records stable source identity before they enter the product workflow.

Self-improvement rule: a specialist may surface a candidate only with owner → observation → evidence → replay → smallest_candidate → confidence → scope. No reproducible evidence means receipt-only no_change. Applied, failed/resumable, and no-change outcomes are all first-class.

The four redundant skills—taste-enhancer, compass-queue-fill, learning-compass-curator-policy, and master-editorial-synthesis—are retired outside the active graph. Their archive copies remain recoverable for audit.

08 · Artifacts

Generated reading material is still tied to a source.

Lite Visual

  1. Resolve the exact source and existing pair.
  2. Mine the complete source and record an evidence packet plus coverage matrix.
  3. Run Visual Mind first when visual assets are needed.
  4. Produce source-proportional HTML and a real tablet/print PDF.
  5. Upload linked roles with checksums, revision metadata, and source identity.
  6. Re-read both artifacts and verify the canonical source record.

There is no subjective Lite Visual QA score or release gate, and Lite Visual never queues Notes Extractor automatically. The PDF is the reading companion; the HTML is the responsive reading surface.

This guide

This document is itself a normal HTML artifact: stored in R2, registered in D1, linked to a canonical source record, and placed in the Queue. It does not become an untracked file dump or a special infrastructure object.

NotebookLM and Obsidian

The Master Corpus receives original sources and Mahmood-authored reflections during explicit feedback workflows. Generated translations and companions are not treated as his thoughts. Obsidian receives extracted-note archive copies only.

10 · Invariants

These rules protect the system from becoming noisy or dishonest.

D1 is canonical

R2 holds large files. Obsidian is an extracted-note archive. No secondary store may silently become authoritative.

Inbox is universal

Telegram, share-target, URL, text, PDF, HTML, video, books, RSS, and Atom captures all enter Inbox.

Queue is finite

Five active items is the default. Overflow is explicit. Weak recommendations never bypass their own override.

Consumption is real

The source is consumed externally and tracked through a learning session. A generated companion is not a substitute for the source.

Notes are editable

Structured notes are searchable, readable, editable, and support per-block English/Egyptian-Arabic direction.

Review is approved

Ratings 7–10 create editable SRS drafts. Approval is required before a card enters Recall.

Feedback does not recommend

Reflection processing updates evidence and proposals, then stops. A new recommendation needs a new explicit request.

No background self-editing

Hermes evolves through explicit workflow evidence, not a hidden cron, poller, or unbounded autonomous loop.

Hard content filters remain active: no book-derived Islamic content; theoretical/philosophical death content only; no dopamine/habit-neuroscience hits; real-life/business storytelling rather than fiction craft; Mathur/ProPublica dark-pattern framing; practical applied AI and agent workflows rather than low-level training math.

12 · Glossary

Names worth keeping straight.

Inbox

The unlimited landing place for every capture before triage.

Queue

The finite set of sources currently queued or in progress. Default cap: five.

Learning Thread

A purpose-first question, decision, build, or capability with evidence requirements and source roles.

Learning Unit

An atomic piece of knowledge with source anchors, personal synthesis, confidence, and typed relations.

Compass

The Thread-first recommendation system with fit, bridge, and challenge lanes and shadow evidence gates.

Hermes

The explicit workflow agent and procedural operating system that operates Learning Compass through validated APIs and specialist skills.

Self-evolution

The evidence-gated process that decides whether a repeated, reproducible observation merits a profile, procedure, skill, code, workflow, or rollout change.

Source record

The canonical joined view of a source, its feedback, sessions, notes, artifacts, recall, units, evidence, proposals, memory influence, and outcome.

Receipt

A durable record of intent, target, before state, mutation or job, after state, evidence, and blocker or terminal decision.
